# Правила работы с источниками
1. **Приоритет проверенных данных:** Использовать данные строго из папки `data/` или официальных логов терминала MT5 / Telegram.
2. **Валидация рядов:** Перед запуском бэктеста всегда проверять временные ряды на пропуски, дубликаты и корректность таймфреймов.
3. **Воспроизводимость:** Любой вывод по паттерну или стратегии должен опираться на зафиксированные параметры и конкретные исторические отрезки.

# Чего не делать (Правила безопасности)
Границы — без явного разрешения не делать:
- ничего, что затрагивает реальные торговые позиции или живых ботов в проде (остановка, перезапуск, прямое изменение логики или исполнение ордеров);
- прямой запуск или передача параметров в лайв-режим без предварительного сохранения конфига в `reports/` и явного подтверждения от Маши;
- git push, коммиты;
- удаление или переименование файлов;
- отправку любых сообщений (в том числе в Telegram-каналы).

Секреты:
- Секреты только в `.env`. В коде — `os.getenv` без дефолтов. Реальные значения в чат/код не вставлять.
- Не писать токены, пароли, proxy login:password, API-ключи как аргументы по умолчанию в `os.getenv("KEY", "...")`.
- Если секрета нет в окружении — скрипт должен падать с явной ошибкой, а не подставлять запасное значение.

Анти-паттерны — раздражает:
- длинные вступления;
- слово «конечно!»;
- пересказ того, что только что было сделано;
- разжёвывание очевидного;
- общение на технических терминах без перевода на обычный язык.

# Структура папок
Стандарт для любого нового проекта — плоско и предсказуемо:

```
myAI/
├── CLAUDE.md          ← системный файл агента (всегда в корне, заглавными)
├── data/              ← данные: CSV, JSON, Excel
├── docs/              ← документы: PDF, Markdown-гайды
├── reports/           ← отчёты и валидированные конфиги параметров
├── scripts/           ← Python-скрипты (паттерны, бэктесты, боты)
└── tmp/               ← временные артефакты работы агента
```

Правила: `CLAUDE.md` только в корне (имя строго заглавными — Claude Code ищет именно так); ничего рабочего не бросать в корень — всё по папкам; `tmp/` считается расходником и в git не попадает.

# Нейминг файлов
Рабочая формула имени файла:

```
[дата — опционально] — [тема] — [тип].md
```

Примеры:
- `2026-04-21-sales-weekly-report.md`
- `client-onboarding-checklist.md`

Правила: строчные латинские буквы, слова через дефис; дата только если файл привязан к моменту (отчёт, срез, лог), формат `ГГГГ-ММ-ДД` в начале — так сортировка по имени = сортировка по времени; тема и тип — существительные, без глаголов и без версий в духе `_final_v2`.
